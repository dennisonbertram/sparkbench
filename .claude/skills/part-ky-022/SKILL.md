# KY-022 infrared receiver module

## Overview
The **KY-022** (also sold as **HW-490**) is the black 3-pin sensor-kit board carrying a **1838-series 38 kHz IR receiver** (VS1838B / TL1838), a 1 kΩ resistor and a red LED that flickers while a signal is received.
- The receiver detects, amplifies, filters and **demodulates** the 38 kHz carrier from an IR remote; S outputs the envelope as a logic signal.
- S **idles high and goes low while IR carrier is received** (active low).
- Range about 18 m, ±45° acceptance angle; supply 3.3–5 V (chip 2.7–5.5 V), 0.4–1.5 mA quiescent.
- The cheap kit remotes (the 17/21-key "car MP3" remotes) use the **NEC** protocol.

## Pinout (3-pin header, as printed on the board)
| Pin | Name | Function |
|-----|------|----------|
| 1 | S | Demodulated signal output, active low |
| 2 | + (middle, often unlabelled) | Supply, 3.3–5 V |
| 3 | - | Ground |

Some clones swap the outer S and - pins; the middle pin is always the supply. Wire by the labels printed on your board.

## Electrical limits
- Supply 2.7–5.5 V (VS1838B datasheet), 6.0 V absolute maximum; the module is specified for 3.3–5 V.
- Output low ≤ 0.4 V; output high ≈ supply (≥ 4.5 V at 5 V). **Powered from 5 V, S idles at 5 V**: with an ESP32 or Pico power the module from 3V3.
- Current 0.4–1.5 mA idle plus about 2 mA in the LED while S is low.

## Interface details
NEC frame as seen on S (low = carrier present):
- 9 ms low (leader mark), 4.5 ms high (space)
- 32 bits, LSB first: address, ~address, command, ~command. Each bit is a 562.5 µs mark followed by a 562.5 µs space (0) or 1687.5 µs space (1)
- A final 562.5 µs mark. While the button is held, a repeat code (9 ms mark, 2.25 ms space, 562.5 µs mark) every 108 ms
- Extended NEC sends a 16-bit address in place of address/~address (use `NEC_16`)

The driver (Peter Hinch's `micropython_ir`, MIT) timestamps every edge in a pin interrupt, then decodes the block 80 ms after the first edge.

## Wiring
| Module | ESP32 | Raspberry Pi Pico | Raspberry Pi 4 |
|---|---|---|---|
| S | GPIO15 | GP16 | GPIO17 (pin 11) |
| + | 3V3 | 3V3(OUT) (pin 36) | 3V3 (pin 1) |
| - | GND | GND | GND |

## Using the driver
```python
from machine import Pin
from ir_rx import NEC_8
import time

def cb(cmd, addr, ctrl):
    if cmd == NEC_8.REPEAT:
        print('repeat')
    elif cmd >= 0:
        print('addr %02x cmd %02x' % (addr, cmd))

ir = NEC_8(Pin(15, Pin.IN), cb)
while True:
    time.sleep_ms(100)
```
`NEC_8` checks the 8-bit address and its inverse; use `NEC_16` for remotes with a 16-bit (extended) address. Negative codes are errors (BADSTART, BADBLOCK, BADDATA, BADADDR...); `ir.error_function(print)` shows them.

## Gotchas
- **No output at all** with correct code: the S and - pins may be swapped on your clone. Check the labels.
- Keep the receiver out of direct sunlight and away from fluorescent/LED lamps; they cause noise bursts.
- The callback runs in a (soft) timer context: keep it short, set a flag and act in the main loop.
- On some ESP32 firmware a software timer `Timer(-1)` is not available: set `IR_RX.Timer_id = 0` (a hardware timer) before creating the decoder.
- The receiver only works with 38 kHz carriers (most consumer remotes). 36/40 kHz remotes give shorter range.
- Long button holds send repeat codes, not the command again: remember the last command if you need auto-repeat.
