# BME280 temperature/humidity/pressure sensor (BME280)

## Overview
The Bosch **BME280** measures temperature, relative humidity and barometric pressure in one 2.5 × 2.5 × 0.93 mm LGA package. It talks over I2C (up to 3.4 MHz) or SPI (3- or 4-wire, up to 10 MHz). Hobbyists usually buy it on a **GY-BME280 4-pin breakout** (VIN, GND, SCL, SDA), wired for I2C at address 0x76. It shares a register layout with the BMP280, which is the pressure-and-temperature-only version.

## Pinout (GY-BME280 4-pin)
| Pin | Function | Notes |
|---|---|---|
| VIN | Supply | 3.3 V recommended |
| GND | Ground | |
| SCL | I2C clock (SPI SCK) | Pull-up usually on board |
| SDA | I2C data (SPI SDI) | Pull-up usually on board |

6-pin boards also break out **CSB** (tie high, or leave it to the board's pull-up, for I2C; pulling it low selects SPI) and **SDO** (GND gives 0x76, VDDIO gives 0x77; it is MISO in SPI mode).

## Electrical limits (datasheet)
- VDD: 1.71–3.6 V. VDDIO: 1.2–3.6 V. Absolute max is 4.25 V.
- Operating range: -40…+85 °C, 0–100 %RH, 300–1100 hPa.
- Current: about 3.6 µA average at 1 Hz with humidity, pressure and temperature all on. Peak current during a conversion is up to about 0.7 mA (pressure). Sleep current is about 0.1 µA.
- Accuracy (typical): ±1 °C, ±3 %RH, ±1 hPa absolute and ±0.12 hPa relative (about ±1 m altitude).
- Not in the datasheet: some breakouts include a 3.3 V regulator and level shifter, so their VIN accepts 5 V. This varies by vendor, so this entry conservatively assumes 3.3 V only.

## Interface details
- **I2C address:** 0x76 with SDO to GND (most GY boards) or 0x77 with SDO to VDDIO (Adafruit and SparkFun boards).
- **Key registers:**
  - `0xD0` chip_id = **0x60**. A BMP280 reads 0x58.
  - `0xE0` reset: write 0xB6.
  - `0x88–0xA1` and `0xE1–0xE7`: calibration constants (dig_T1–T3, P1–P9, H1–H6).
  - `0xF2` ctrl_hum: osrs_h[2:0]. Takes effect only after a write to ctrl_meas.
  - `0xF3` status: bit 3 = measuring, bit 0 = im_update.
  - `0xF4` ctrl_meas: osrs_t[7:5], osrs_p[4:2], mode[1:0] (00 sleep, 01 forced, 11 normal).
  - `0xF5` config: t_sb[7:5], filter[4:2], spi3w_en[0].
  - `0xF7–0xF9` pressure (20-bit), `0xFA–0xFC` temperature (20-bit), `0xFD–0xFE` humidity (16-bit). All big-endian; the xlsb byte uses bits 7:4.
- **Compensation:** every reading must be converted using the factory constants. Temperature is calculated first because it produces `t_fine`, which the pressure and humidity formulas need. The supplied driver implements the floating-point formulas from datasheet section 8.1.
- **Timing:** one forced conversion at ×1 oversampling takes about 8 ms (maximum 9.3 ms).

## Wiring
| Board | VIN | GND | SDA | SCL |
|---|---|---|---|---|
| ESP32 | 3V3 | GND | GPIO21 | GPIO22 |
| Raspberry Pi Pico | 3V3(OUT) pin 36 | GND | GP4 (I2C0) | GP5 (I2C0) |
| Raspberry Pi 4 | Pin 1 (3.3 V) | Pin 6 | Pin 3 (GPIO2) | Pin 5 (GPIO3) |

On the Pi 4, enable I2C with `raspi-config`, then check that the sensor shows up with `i2cdetect -y 1`.

## Using the driver
```python
from machine import I2C, Pin
from bme280 import BME280
import time

i2c = I2C(0, sda=Pin(4), scl=Pin(5), freq=400000)  # Pico; ESP32: sda=21, scl=22
print([hex(a) for a in i2c.scan()])
bme = BME280(i2c, addr=0x76)
while True:
    t, p, h = bme.read()
    print("%.2f C  %.2f hPa  %.1f %%RH" % (t, p, h))
    time.sleep(2)
```

## Gotchas
- **BMP280 vs BME280:** many cheap "BME280" boards are really BMP280s, which have no humidity sensor. Check chip ID 0x60. On the chip itself, the BME280 package is square and the BMP280 is rectangular.
- If nothing appears at 0x76, try 0x77.
- Write ctrl_hum before ctrl_meas, or the humidity reading stays at 0x8000 (skipped).
- Running in normal mode at a high data rate warms the sensor. For weather logging, use forced mode at ×1 oversampling with the filter off.
- Mount the sensor away from heat sources, and keep the vent hole on the metal lid uncovered.
- Pressure gives altitude only relative to the current sea-level pressure, so pass your local QNH to `altitude()`.
