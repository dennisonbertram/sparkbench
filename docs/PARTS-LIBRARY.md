# Parts library

Generated by `npx tsx scripts/parts/report.ts`. How a part gets in: [the part check](../scripts/parts/check.ts) (wiring, design checks, breadboard plan, simulator example + test on ESP32 and Pico, KiCad footprint, a routed DRC-clean circuit board, LCSC stock) and then [publish](../scripts/parts/publish.ts), which compares the part with a blind second reading of the datasheet (header pin order, roles, I2C address, supply range, conversion constants, chip ID). Any disagreement goes to review instead of the library.

**Nothing here has been tested on real hardware yet.** "Checked" means the simulator, the circuit-board tools and two independent datasheet readings agree.

## Didn't make it

| Part | Outcome | Why |
|---|---|---|
| MS5611 | unsupported | The MS5611 returns both D1 (pressure) and D2 (temperature) from the same ADC-read command 0x00, chosen by the preceding one-byte conversion command (0x40-0x48 vs 0x50-0x58). The i2c-device sim can't do this: a bare command byte stores no register data, so measure.when can't see it, and a 'responses' reply is cleared by the 0x00 write the real driver must send. D1 also depends on both temperature and pressure through the PROM compensation, which the per-control linear measures can't encode. |
| Capacitive soil moisture sensor v1.2 | duplicate | lookup.ts reports the part is already in Sparkbench as built-in 'soil' (Capacitive soil moisture sensor); nothing added. |
| DRV8825 | unsupported | The DRV8825 has no logic-supply pin: its internal regulator runs from VMOT, which TI and Pololu specify as 8.2-45 V, but Sparkbench can only power a part from the board's 3.3 V or 5 V pins (no external motor supply). Powered from 5 V, design checks flag an under-voltage error and the simulator treats the part as unpowered, so its inputs never read as active. Lowering vmin to make the check pass would tell beginners the board runs at 5 V when it does not. |
